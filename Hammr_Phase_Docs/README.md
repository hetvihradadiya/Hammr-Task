# Hammr Phase Documentation

Use these documents in order. Do not skip ahead to stretch features
before the mandatory auction system works.

1.  `00-project-overview.md` --- project scope and priorities
2.  `01-phase-0-setup.md` --- machine and developer setup
3.  `02-phase-1-foundation.md` --- monorepo, TypeScript, ESLint,
    Prettier, Husky
4.  `03-phase-2-infrastructure.md` --- PostgreSQL, Prisma, Redis
5.  `04-phase-3-database.md` --- schema and seed data
6.  `05-phase-4-auth.md` --- authentication, authorization, 2FA
7.  `06-phase-5-seller-auctions.md` --- seller auction management
8.  `07-phase-6-bidding-engine.md` --- transactional/concurrent bidding
9.  `08-phase-7-lifecycle-jobs.md` --- automatic auction lifecycle
10. `09-phase-8-realtime.md` --- Socket.IO and notifications
11. `10-phase-9-frontend.md` --- Next.js UI
12. `11-phase-10-payments-extra-features.md` --- payment and supporting
    mandatory features
13. `12-phase-11-testing-security.md` --- tests and hardening
14. `13-phase-12-deployment.md` --- deployment and delivery
15. `14-command-checklist.md` --- quick command reference
16. `15-final-definition-of-done.md` --- final checklist

## Working rule

Complete each phase, test it, commit it, then move to the next phase.

The 3-day deadline means scope control is more important than adding
stretch features.
